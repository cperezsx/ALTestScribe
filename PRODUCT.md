# Product

## Register

brand

## Users

Business Central AL developers and QA engineers who execute tests in Visual Studio Code and need a dependable, local record of failures after the test output has disappeared.

## Product Purpose

AL TestScribe turns failed AL test notifications into timestamped local reports. It is deliberately a recorder, not a test runner, CI system, or automated fix agent. Success means a developer can run tests normally and later find a complete, well-structured failure report without copying terminal output by hand.

## Brand Personality

Evidence-first, calm, and technical. The product should feel like a dependable development instrument that records what happened without making a decision on the user's behalf.

## Anti-references

Avoid noisy test dashboards, fake AI-assistant claims, opaque background uploads, aggressive failure visuals, and generic SaaS marketing language. Never imply that the extension fixes tests or analyzes data outside the local workspace.

## Design Principles

1. Preserve evidence, then get out of the way.
2. Make the saved-file destination and export outcome obvious.
3. Respect the existing AL test workflow rather than replacing it.
4. Explain boundaries honestly, especially AL-version compatibility and data locality.
5. Keep hand-off neutral: users decide how to read, share, or process reports.

## Accessibility & Inclusion

Target WCAG 2.1 AA for public documentation and GitHub Pages. Use semantic HTML, visible keyboard focus, readable contrast, descriptive alternative text, and reduced-motion support. Never use color as the only indication of a failed test.
